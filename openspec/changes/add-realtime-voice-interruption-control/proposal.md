# Proposal

## Why

当前语音链路以按住说话和释放提交为主，无法在 Mira 播放时自然识别用户开口；短促的“嗯”“对”等附和还可能被误判为新指令，导致语音、字幕和场景被不必要地打断。实时语音体验还需要回声消除、流式字幕、延迟可观测性，以及断线后的安全恢复，才能接近自然对话。

## What Changes

- 增加持续音频采集下的语音活动检测（VAD）和实时 ASR 增量识别。
- 将短附和、犹豫声与有明确意图的用户发言分类；附和不取消 Mira 当前输出，真实打断才取消并切换到新输入。
- 为真实打断支持明确关键词、稳定终稿和最小语义长度等确认策略，降低误触发。
- 在采集链路加入浏览器回声消除、降噪和自动增益配置，并在不可用时提供降级提示。
- 将实时识别结果以流式字幕展示，区分临时文本、已确认文本和最终提交文本。
- 展示首包语音延迟、ASR/LLM/TTS/播放等关键阶段耗时，并标识重连与恢复状态。
- 为 WebSocket/ASR 会话增加断线重连、指数退避、会话恢复和重复结果去重；恢复失败时保持文本输入可用。
- 保持现有按住说话、文本提交和跨会话取消语义；显式按住说话仍视为用户主动打断。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `interruptible-character-conversation`: 修改实时语音输入、用户打断、字幕同步、失败恢复和可观测性要求。
- `mira-interactive-scene`: 增加实时听取、确认打断、流式字幕和连接状态的可见反馈要求。

## Impact

- 客户端音频采集、音频播放和字幕状态机。
- WebSocket 会话协议、ASR 适配器、会话协调器及取消/恢复逻辑。
- 语音供应商配置与浏览器 MediaStream 音频约束（AEC、降噪、AGC）。
- 性能埋点和调试面板/状态提示；需要新增分类、重连、竞态和端到端语音测试。
